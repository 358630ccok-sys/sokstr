# Case Study: Job Hunter Bot (автоматизация поиска вакансий)

## Контекст и задача
**Проблема:** ручной поиск DevOps/MLOps-вакансий на нескольких площадках занимает время и легко пропускает новые публикации.  
**Цель:** автоматизировать сбор вакансий и доставку структурированного отчёта в Telegram по расписанию.

## Решение
Реализован Python-сервис `job_bot/job_hunter.py`, который:
- собирает вакансии из **hh.ru API** (и опционально использует токен) и **LinkedIn** (guest endpoint/RSS fallback)
- формирует единый текстовый отчёт (название, зарплата, ссылка)
- отправляет отчёт в Telegram (Bot API, aiogram)
- поддерживает запуск по расписанию (cron/systemd timer/контейнер) и **безопасный demo-режим** (`--demo`) без сети и без отправки сообщений

## Архитектура (упрощённо)
```text
[Scheduler/Cron] -> [job_hunter.py] -> [hh.ru API / LinkedIn] -> [форматирование отчёта] -> [Telegram Bot API] -> [чат/канал]
                                      \-> [логи/ошибки API/парсинга]
```

## Эксплуатация и проверка
- **Конфигурация:** `.env` (токены/чат-ID не хранятся в git, есть `.env.example`)
- **Деплой:** локально (venv) или Docker (`job_bot/Dockerfile`)
- **Проверка корректности:**
  - `python3 job_bot/job_hunter.py --demo` — проверка формата/логики без внешних зависимостей и отправки
  - сверка части найденных вакансий с источником (hh.ru)
  - контроль логов и ошибок запросов/парсинга
  - проверка доставки/формата сообщения в Telegram

## Результат
- Регулярная автоматическая подборка вакансий без ручного мониторинга площадок
- Единый формат отчёта для быстрого просмотра
- Воспроизводимый запуск (Docker/.env) и безопасный способ демонстрации (`--demo`)

## Сценарий использования командой/другим пользователем
Сервис можно развернуть для общего чата/канала:
1. Создать Telegram-бота и получить `TG_TOKEN`
2. Добавить бота в общий чат/канал и указать `TELEGRAM_CHAT_ID`
3. Настроить `.env` и запуск по расписанию (cron/systemd/Docker)
4. Участники получают регулярные отчёты с подборкой вакансий в одном месте

> Примечание: доступы (токен бота, chat ID) должны храниться как секреты и выдаваться по принципу минимальных прав.

# AGENTS.md — правила работы для AI-агентов в репозитории

## Цель
Использовать AI-агентов для ускорения диагностики, автоматизации и разработки **без ущерба безопасности, воспроизводимости и качества**.

## Общие правила
- **Безопасность прежде всего:** не добавлять в git секреты, токены, пароли, приватные ключи, cookies, `.env` с реальными значениями. Использовать `.env.example`.
- **Минимальные права:** не выполнять разрушительные операции (удаление, перезапуск хостов/сервисов, массовые изменения) без явного запроса/подтверждения.
- **Малые шаги:** делить задачу на этапы (анализ → изменение → проверка), чтобы быстро находить ошибки.
- **Проверяемость:** каждое изменение сопровождать проверкой (логи, вывод команд, smoke-check, сверка результата с источником/ожиданием).
- **Документирование:** фиксировать важные изменения в README/runbooks/заметках (что сделано, как проверить, как откатить/восстановить).

## Workflow (задача → результат)
1. **Уточнить цель и критерии готовности** (что должно работать, где и как проверить).
2. **Собрать контекст** (файлы, конфиги, логи, метрики, зависимости), не раскрывая секреты.
3. **Внести минимально достаточные изменения** (код/конфиг/документация).
4. **Проверить результат:**
   - логи/код возврата (`journalctl`, `docker logs`, вывод CLI)
   - состояние сервисов/healthchecks
   - сверка данных с источником (API/БД/метрики/ожидаемый вывод)
5. **Зафиксировать итог** (коммит, обновление docs/runbooks, краткий отчёт).

## Проверки для этого репозитория
- **Python (`job_bot/`):** синтаксис/запуск в тестовом режиме, корректность формата сообщений, работа с `.env.example`.
- **Документация:** ссылки и пути к файлам/скриншотам корректны, команды воспроизводимы.
- **Инфраструктурные runbooks:** шаги диагностики/восстановления, явная проверка результата (в т.ч. restore-проверка для БД).

## Автоматизация (существующая)
- `job_bot/job_hunter.py` — сбор вакансий (hh.ru, LinkedIn) и отправка отчёта в Telegram по расписанию/запуску.
- При изменениях бота: сохранять совместимость с `.env`, не логировать секреты, проверять обработку ошибок API/парсинга.
